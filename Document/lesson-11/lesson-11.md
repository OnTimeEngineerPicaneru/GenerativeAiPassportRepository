## 2. 要件定義の体験：作りたいものを整理する

いきなりコードを作り始める前に、「何を作るか」をはっきりさせることが大切。これを **要件定義** という。

### なぜ要件定義が必要か？

要件定義なしで開発を始めると：

- 「途中で作りたいものが変わってしまう」
- 「できあがったものが思っていたものと違う」
- 「機能が増えすぎて収拾がつかなくなる」

こういった問題が起きやすい。プロの開発現場でも要件定義は最初の重要なステップ。

### 要件定義シート（記入してみよう）

| 項目 | 内容 |
|------|------|
| アプリ名 | |
| 作る理由・使う場面 | |
| 主な機能（やれること）| ① ② ③ |
| 使う人のイメージ | |
| 完成のイメージ（どう見えるか・どう使うか）| |
| 作らないこと（スコープ外）| |

### AI と相談しながら設計する

要件定義シートを書いたら、AI に相談してみよう。

```
私は Python でアプリを作りたいです。
以下の内容で考えているのですが、機能を整理・改善するアドバイスをください。

・アプリ名：クイズゲーム
・主な機能：
  1. 問題が 5 問出る（生成 AI に関する問題）
  2. 各問題に 2 択で答える
  3. 最後にスコアを表示する

このアプリを作るときに、追加すると面白くなる機能や注意点があれば教えてください。
また、Lesson 1 で作れる最小限のバージョンから始めるための機能リストを提案してください。
```

**AI のアドバイスを受けて**、要件定義シートを更新しよう。

## 3. 実習：AI と対話しながらアプリを作る

### ステップ 1：基本機能を作る（MVP：最小限の動く製品）

まず、一番シンプルな形（最小限の機能）を作ることを目指そう。これを **MVP（Minimum Viable Product）** という。

```
（例：クイズゲームの場合）

Python で次の仕様のクイズゲームを作ってください。

仕様：
- 問題を 3 問用意する（テーマ：生成 AI パスポートの内容）
- 各問題に対して 2 択で答える（1 か 2 を入力）
- 正解・不正解をその都度表示する
- 最後にスコア（○問正解 / 3 問中）を表示する

コメント付きのコードを出力してください。
```

**確認チェックリスト（ステップ 1 完了条件）**

- [ ] エラーなく実行できるか？
- [ ] 3 問すべて出題されるか？
- [ ] 正解・不正解が正しく判定されるか？
- [ ] スコアが最後に表示されるか？

### ステップ 2：機能を追加・改良する

基本が動いたら、少しずつ機能を追加していこう。

```
（改良指示の例）

今のクイズゲームに以下の機能を追加してください：
・問題の順番をランダムにする
・正解数に応じてメッセージを変える
  （例：全問正解なら「完璧！」、半分以下なら「もう一度チャレンジ！」）
```

**追加機能のアイデア**

| 機能 | 難易度 |
|------|--------|
| 問題のランダム順序 | 低 |
| スコアに応じたメッセージ | 低 |
| タイムアタック（制限時間） | 中 |
| 問題数を選べる | 中 |
| 間違えた問題の振り返り | 中 |
| 記録の保存（CSV 書き込み） | 高 |

### ステップ 3：エラーへの対処

エラーが出たときは、前回学んだエラー報告の方法で AI に伝えよう。

```
以下のコードを実行したらエラーが出ました：

【コード】
（エラーが起きているコード部分を貼り付ける）

【エラーメッセージ】
（エラーメッセージをそのまま貼り付ける）

【目標】
このコードで○○をしたいです。
エラーの原因と修正方法を教えてください。
```

**よくあるエラーと原因**

| エラー名 | 意味 | よくある原因 |
|---------|------|-----------|
| `SyntaxError` | 文法エラー | カッコの閉じ忘れ・インデントのズレ |
| `NameError` | 変数が定義されていない | 変数名のスペルミス |
| `IndexError` | リストの範囲外 | リストの要素数より大きい番号を指定 |
| `ValueError` | 値の型が違う | 数字が必要な場所に文字列が入っている |

### ステップ 4：コードを理解する

完成したら、AI にコードの説明を求めてみよう。

```
上記のコードについて、
・このコード全体の流れを日本語で説明してください
・特に重要な部分（ここを変えると動作が変わる箇所）を教えてください
・このコードを改良するとしたら、次にどんな機能を追加できますか？
```

## 5. 発表（75〜90分）

完成したアプリをクラスに発表しよう。

### 発表の構成（1 人 2〜3 分）

1. **何を作ったか**：アプリの名前と概要を 1 文で説明する
2. **デモ**：実際に動かして見せる
3. **工夫した点**：こだわったポイントや追加した機能を話す
4. **難しかった点**：どんなエラーや問題があったか、どう解決したかを話す
5. **次にやりたいこと**：もし時間があればこんな機能を追加したかった

### フィードバックのポイント

発表を聞く側は、次のことを意識してフィードバックしよう：

- 良かった点は「〇〇が面白かった」と**具体的に**伝える
- 改善点は「〇〇ができたらもっと使いやすくなりそう」と**提案型**で伝える
- 「なぜそのアイデアが浮かんだのか」を聞いてみよう

## 6. AI との協働から学ぶこと

この体験を通じて気づいてほしいこと：

### ポイント 1：AI は「ゼロから作る」作業を代わりにやってくれる

でも、「何を作るか」「どう改良するか」「何がうまくいっていないか」という判断は自分が行う。

### ポイント 2：指示の質が出力の質を決める

曖昧な指示からは曖昧な結果しか生まれない。「クイズゲームを作って」より「問題が 5 問出て、2 択で答えて、最後にスコアが出るクイズゲームを Python で作って」の方が、求める結果に近い。

### ポイント 3：失敗は学びのチャンス

エラーや思い通りにいかないことは、プログラミングでは当たり前。AI と対話しながら粘り強く改善する姿勢が重要。

### ポイント 4：AI の力を借りても、完成させる責任は自分にある

最終的な内容・品質・使い方への責任は、使った人間が負う。「AI が作ったから」は免責の理由にならない。
